# Spring Boot Profile Switcher — Плагин для IntelliJ IDEA

[![IntelliJ Platform](https://img.shields.io/badge/IntelliJ%20Platform-2022.2%2B%20%7C%202024.x%2B%20%7C%202026.x%2B-blue.svg)](https://plugins.jetbrains.com/)
[![Version](https://img.shields.io/badge/Version-1.0.24-brightgreen.svg)]()

**Spring Boot Profile Switcher** — плагин для среды разработки IntelliJ IDEA, созданный для удобного управления конфигурационными профилями и запуска приложений на **Spring Boot (2.x – 3.x)**.

Плагин автоматизирует переключение активных профилей и файлов конфигураций (`application*.yml` / `application*.yaml`), управляет многостадийным конвейером запуска (автоматическое наложение и откат Git-патчей, предварительная сборка, запуск сервиса), отображает статус запуска приложения в реальном времени, форматирует вывод терминала и предоставляет встроенную студию диагностики логов и ошибок.

## Ключевые возможности

- 🔍 **Автоматическое обнаружение конфигураций**: мгновенное сканирование `src/main/resources` по всем модулям проекта и дополнительных каталогов для файлов `application*.yml` и `application*.yaml`.
- 🎛️ **Удобный ComboBox в панели инструментов**: отображение активного профиля с галочкой и кнопками быстрого запуска, перезапуска, остановки, сравнения конфигураций и перехода в настройки.
- 🧩 **Многостадийный Pre-Run конвейер**:
  - Наложение Git-патчей (`.patch` / `.diff`) перед сборкой.
  - Автоматический сброс локальных изменений (`git checkout -- <file>`) перед наложением патча для гарантии чистоты рабочего дерева.
  - Выполнение настраиваемой команды сборки (например, `mvn clean package` или `mvn -T 8 -o "-Dmaven.test.skip=true"`).
  - Автоматический откат всех наложенных патчей (`git apply -R`) сразу по окончании сборки (при успехе или ошибке), возвращающий рабочее дерево в исходное состояние до запуска приложения.
  - Опциональный пропуск pre-run сборки при переключении профиля, если приложение уже запущено.
- 🚦 **Индикатор фаз запуска в реальном времени**:
  - `Сборка...` (синий) — этап предварительной сборки.
  - `Tomcat: <port>` (серый) — запуск встроенного сервера Tomcat и фиксация порта.
  - `WatchDir started` (желтый) — инициализация файлового наблюдателя.
  - `Started: <port>` (зеленый) — приложение успешно запущено и готово к приему запросов.
  - `ОШИБКА` (красный) — индикация падения процесса или ошибки сборки.
- 📟 **Интеллектуальная консоль терминала**:
  - Подсветка строк с ошибками (`ERROR`, `Exception:`, `Caused by:`) ярко-красным цветом ANSI.
  - Автоматическое подавление длинных Java/Tomcat стек-трейсов (`at ...`, `... N more`) для чистоты логов при сохранении сообщений об исключениях и причин (`Caused by:`).
- 🔬 **Студия диагностики логов и ошибок (Log & Error Diagnostic Studio)**:
  - Специализированное окно инспекции сетевых запросов GraphQL и классификации ошибок приложения.
  - Автоматическая категоризация сбоев (`GraphQL Server`, `Validation`, `HTTP 5xx`, `HTTP 4xx`, `Timeout`, `App Exception`), выявление корневых причин (`Root Cause`), интерактивный стек-трейс с быстрым переходом к коду (`Jump to Source`) и визуальное сравнение (`Diff`) с успешными ответами.
  - Встроенный сканер логов (`session.log`) с фильтрацией по уровням (`DEBUG`, `INFO`, `WARN`, `ERROR`).
- ⚖️ **Встроенный Diff Viewer**: сравнение любого профильного YAML-файла с базовым `application.yml` в один клик через стандартный Diff-инструмент IntelliJ IDEA.
- 🌐 **Двуязычный интерфейс и контекстная справка**:
  - Полная поддержка Русского и Английского языков.
  - Автоматическое применение языка системы при первом запуске.
  - Мгновенное переключение языка в настройках на лету без перезагрузки IDE.
  - Синие векторные значки помощи `?` с подробными всплывающими подсказками к каждому элементу управления.

## Установка плагина в IDE

1. Загрузите архив плагина `spring-boot-profile-switcher-1.0.24.zip` (из раздела релизов).
2. Запустите **IntelliJ IDEA**.
3. Откройте окно настроек:
   - В Windows/Linux: **File ➔ Settings...** (или нажмите `Ctrl + Alt + S`).
   - В macOS: **IntelliJ IDEA ➔ Settings...** (или нажмите `Cmd + ,`).
4. В левом меню выберите раздел **Plugins** (Плагины).
5. В верхней части панели нажмите на значок шестерёнки (**⚙**) и выберите пункт **Install Plugin from Disk...** (Установить плагин с диска...).
6. В открывшемся файловом проводнике выберите файл `spring-boot-profile-switcher-1.0.24.zip` и нажмите **OK**.
7. Нажмите **Apply** (Применить), затем **Restart IDE** (Перезагрузить среду) для завершения установки.

## Пользовательский интерфейс и возможности

### 1. Переключатель профилей в тулбаре (ComboBox)

Виджет располагается в панели навигации (`NavBarToolBar`) и на панели инструментов справа (`MainToolbarRight`).

- **Отображение активного профиля**: имя выбранного профиля отображается прямо на кнопке (например, `Profile: dev` или `Профиль: local`).
- **Меню переключения**: клик по выпадающему списку открывает перечень всех доступных конфигурационных файлов проекта с отметкой активного галочкой.
- **Быстрые действия в меню**:
  - ▶️ **Запуск / Перезапуск** (`Run / Restart`) — запуск выбранной конфигурации.
  - ⏹️ **Остановить** (`Stop`) — завершение активного процесса приложения.
  - 🔄 **Пересобрать и перезапустить** (`Rebuild and Restart`) — принудительный запуск конвейера сборки и старта.
  - ⚖️ **Сравнить с application.yml** (`Compare with application.yml`) — открытие визуального диффа.
  - 🔬 **Анализатор логов и ошибок** (`Log & Error Analyzer`) — вызов окна анализа логов и запросов.
  - 📁 **Открыть папку логов** (`Open Log Folder`) — быстрый переход к файлам диагностики плагина.
  - ⚙️ **Настройки конфигураций...** (`Configuration Settings...`) — прямой переход в окно настроек.

### 2. Многостадийный конвейер запуска и Git-патчи

Плагин реализует безопасный конвейер выполнения (Pipeline), состоящий из четырех последовательных фаз:

```
[Старт] 
   │
   ▼
[Фаза 1: Git-патчи] ────► git checkout -- <файлы> (чистый baseline)
   │                      git apply --whitespace=nowarn <патч>
   ▼
[Фаза 2: Pre-Run сборка] ─► Выполнение команды (например, mvn -T 8 -o ...)
   │
   ▼
[Фаза 3: Автооткат] ────► git apply -R <патчи> (откат изменений в обратном порядке)
   │
   ▼
[Фаза 4: Запуск сервиса] ─► java -jar ... --spring.profiles.active={profile},auth-dev
```

#### Инвариант чистоты рабочего дерева:
Перед применением любого Git-патча плагин анализирует список файлов, модифицируемых патчем, и автоматически выполняет `git checkout -- <file>` для устранения нескоммиченных локальных правок. Это предотвращает конфликты и гарантирует повторяемость сборки.

#### Автоматический откат патчей:
Сразу по завершении шага сборки (как при успешной компиляции, так и при ошибке), плагин незамедлительно откатывает наложенные патчи командой `git apply -R`. Это оставляет рабочую копию чистой и готовой к повседневной разработке, пока приложение запускается и работает в фоне.

#### Диалог вставки патча из буфера обмена:
В окне настроек плагина доступна кнопка **"Вставить из буфера..."** (**Paste from Clipboard...**): плагин распознает содержимое unified diff в буфере обмена, предлагает автосгенерированное имя файла (`custom-<timestamp>.patch`) и сохраняет его в папку `<проект>/.idea/patches/`.

### 3. Индикатор статуса запуска приложения (App Status Widget)

В реальном времени информирует разработчика о том, на какой стадии находится запуск приложения:

| Фаза | Индикатор | Описание |
| :--- | :--- | :--- |
| **0. Сборка** | 🔵 `Сборка...` / `Building...` | Идет выполнение предварительной команды сборки (Maven/Gradle). |
| **1. Tomcat** | ⚪ `Tomcat: 8080` | Обнаружен запуск встроенного контейнера сервлетов и порт (`Tomcat started on port(s): ...`). |
| **2. WatchDir** | 🟡 `WatchDir started` | Файловый наблюдатель инициализирован (`WatchDir is started`). |
| **3. Готов** | 🟢 `Started: 8080` | Приложение успешно стартовало (`Started ... in ... seconds` / `Application started`) и готово к работе. |
| **4. Ошибка** | 🔴 `ОШИБКА` / `ERROR` | Отображается **только** в случае, если процесс сборки завершился сбоем или процесс приложения упал/остановлен. |

> **Примечание**: Некритичные ошибки и предупреждения в процессе работы запущенного сервиса не переводят виджет в красное состояние.

### 4. Терминал: ANSI-подсветка и фильтрация стек-трейсов

Все команды конвейера запуска выводятся в окно встроенного терминала IntelliJ Terminal:

- **Цветное выделение ошибок**: строки лога, содержащие маркеры `ERROR`, `Exception:` или `Caused by:`, автоматически подсвечиваются ярким красным цветом ANSI (`\u001B[91m`).
- **Скрытие громоздких стек-трейсов**:
  - Строки трассировки стека вызовов Java и Tomcat (`at org.springframework...`, `... 45 more`, `- locked <...>`) подавляются из консоли терминала при включенной опции **Скрыть стек вызовов ошибок** (включена по умолчанию).
  - При этом сами строки с описанием ошибки и корневыми причинами (`Caused by: ...`) полностью сохраняются и выделяются красным.
  - Это позволяет мгновенно увидеть суть проблемы без необходимости прокручивать тысячи строк логов.

### 5. Студия диагностики логов и ошибок (Log & Error Analyzer)

Доступна через ComboBox тулбара, отдельную кнопку на панели инструментов или меню **Tools ➔ Log & Error Analyzer**:

- **Студия диагностики ошибок (Error Diagnostic Studio)**:
  - **Автоматическая классификация сбоев**: определение типа ошибки (`GraphQL Server`, `Validation`, `HTTP 5xx`, `HTTP 4xx`, `Timeout`, `App Exception`).
  - **Анализ первопричин (Root Cause)**: автоматическое выделение корневой причины исключения и ключевых метаданных (HTTP-статус, задержка, эндпоинт, таймстемп).
  - **Быстрый переход к коду (Jump to Source)**: интерактивная навигация по стек-трейсу с кнопками перехода в файл и строку приложения (`Jump to App Source`, `Jump to Line`).
  - **Визуальное сравнение (Diff)**: сопоставление сбойного запроса/ответа с успешным (`Compare with Success`) в нативном двухпанельном Diff-вьювере.
  - **Экспорт отчетов**: копирование структурированного Markdown-отчета об ошибке для баг-трекера в один клик.
- **Инспектор сетевых запросов (GraphQL Inspector)**:
  - Перехват и форматирование GraphQL-запросов, переменных (Variables) и ответов сервера (JSON).
  - Генерация готовых команд `cURL` для воспроизведения запроса в терминале.
  - Замер времени ответа (Latency) и фильтрация по типу операции (`QUERY`, `MUTATION`) и статусу выполнения.
- **Сканер логов (Log Scanner)**:
  - Автоматическое сканирование логов текущего прогона из `session.log`.
  - Поиск по тексту и фильтрация по уровням логирования (`DEBUG`, `INFO`, `WARN`, `ERROR`).
  - Диалог вставки произвольного фрагмента лога (`Paste Log`) для быстрой диагностики.
  - Быстрый переход в каталог с лог-файлами (`Open Log Folder`).

### 6. Встроенный инструмент сравнения (Diff Viewer)

Позволяет в один клик визуально сопоставить любой профильный файл конфигурации (например, `application-prod.yml` или `application-dev.yml`) с базовым файлом `application.yml`:
- Задействует нативный двухпанельный редактор сравнения IntelliJ IDEA.
- Наглядно подсвечивает добавленные, измененные и переопределенные свойства.

### 7. Локализация и интерактивные подсказки

- **Автоматическое определение локали**: при первом запуске плагин проверяет язык системы. Если установлена русская локаль (`ru`), интерфейс сразу активируется на русском языке; в остальных случаях — на английском.
- **Динамическое переключение**: при смене языка в окне настроек все подписи, заголовки секций, кнопки и всплывающие подсказки обновляются мгновенно без необходимости перезапуска среды.
- **Интерактивные значки помощи `?`**: рядом с каждым полем настройки расположен стильный синий значок с векторным знаком вопроса. Наведение курсора мыши открывает подробное руководство и подсказку по использованию соответствующей опции.

### 8. Интеграция с браузером: расширение GraphiQL Links

Для удобной работы с GraphQL-запросами плагин комплектуется расширением для Google Chrome — **GraphiQL Links** (каталог `chrome-mesh-extension`).

#### Возможности:
- В панели **Log & Error Analyzer** по нажатию кнопки **«Open in Mesh»** формируется ссылка на веб-консоль GraphiQL с закодированным телом запроса и переменными:
  ```text
  https://<graphiql-host>/graphiql/index.html?query=<encoded GraphQL>&variables=<encoded JSON>
  ```
- Расширение Chrome автоматически перехватывает ссылку, открывает её в новой вкладке GraphiQL, заполняет поля Query и Variables через CodeMirror и автоматически инициирует выполнение запроса.
- Предотвращает ошибки переполнения URL (Nginx 414 Request-URI Too Large) путем прозрачной трансформации параметров запроса.

#### Установка расширения в Google Chrome:
1. Загрузите архив `chrome-mesh-extension-1.0.24.zip` из раздела релизов (Releases) или используйте каталог `chrome-mesh-extension` из репозитория.
2. Распакуйте архив в удобную папку.
3. Откройте страницу `chrome://extensions` в браузере.
4. Включите переключатель **Режим разработчика** (**Developer mode**).
5. Нажмите **Загрузить распакованное расширение** (**Load unpacked**) и укажите распакованную папку с расширением.

## Настройки плагина

Окно параметров доступно через **Settings ➔ Tools ➔ Spring Boot Profile Switcher** (или пункт меню *Настройки конфигураций...* в выпадающем списке тулбара).

### Описание разделов настроек:

1. **Язык интерфейса (Language)**
   - Выбор языка отображения плагина: `Русский (RU)` или `English (EN)`.
2. **Патчи Git (Git Patches)**
   - Таблица подключаемых `.patch` / `.diff` файлов с чекбоксами активации и привязкой к профилям.
   - Кнопка **"Вставить из буфера..."** для быстрого добавления патча.
   - Чекбокс **"Сброс изменений перед наложением патча"** (`git checkout -- <file>`).
   - Чекбокс **"Автооткат патчей после сборки"** (`git apply -R`).
   - Каталог хранения патчей (по умолчанию `.idea/patches`).
3. **Сборка перед запуском (Pre-Run Build)**
   - Чекбокс активации шага предварительной сборки.
   - Поле команды сборки (например, `mvn clean package`).
   - Чекбокс **"Пропустить pre-run сборку, если приложение уже запущено"** (позволяет быстро переключать профили без повторной долгой компиляции).
4. **Команда запуска приложения (Run Command Template)**
   - Шаблон исполняемой команды с поддержкой макроса `{profile}` (по умолчанию включает профиль авторизации `,auth-dev`):
     ```bash
     java -jar target/server.jar --debug --spring.profiles.active={profile},auth-dev
     ```
   - Кнопка **"Пересчитать"** для автоматического определения JAR-файла и формирования команды с `{profile},auth-dev`.
5. **Логирование и консоль терминала**
   - Уровень логирования плагина (`DEBUG`, `INFO`, `WARN`, `ERROR`).
   - Чекбокс **"Выделять ошибки в логах красным цветом"** (ANSI-подсветка).
   - Чекбокс **"Скрыть стек вызовов ошибок (Call stack)"** (подавление шума в консоли).
6. **GraphQL / Анализ ошибок**
   - Чекбокс включения инспектора сетевых запросов.
   - URL эндпоинта GraphQL.
   - Максимальный размер истории запросов.
7. **Диагностика и логи плагина**
   - Кнопка **"Открыть папку с логами"** для быстрого доступа к логам плагина.
